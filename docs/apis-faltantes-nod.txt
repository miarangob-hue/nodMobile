APIs FALTANTES PARA NOD
=======================

Fecha de revisión: 25-09-2026

Alcance
-------
Este documento contiene solamente las APIs que faltan para que las funciones
nuevas de Matches, notificaciones, seguridad y experiencia del servicio sean
reales y se sincronicen entre distintos teléfonos.

No se incluyen las APIs que la aplicación ya consume para login, clientes,
proveedores, mascotas, reservas, ruta GPS, fotos del servicio, chat de reservas,
incidentes, soporte, wallet y onboarding.

Convenciones
------------
- Autenticación: Authorization: Bearer <access_token>
- El backend debe obtener y validar el usuario desde el token. Los customer_id
  recibidos desde el cliente no deben considerarse una autorización.
- Fechas: ISO-8601 UTC.
- IDs: UUID.
- Error estándar:
  {
    "error": "codigo_estable",
    "message": "Mensaje legible",
    "details": null
  }


PRIORIDAD 1 - MATCHES ENTRE TELÉFONOS
=====================================

1. GET /discovery/candidates
----------------------------
Query:
  pet_id=<uuid>
  customer_id=<uuid>
  cursor=<string opcional>
  limit=<1..30>

Respuesta:
{
  "items": [
    {
      "pet_id": "uuid",
      "display_name": "Luna",
      "age_months": 30,
      "species": "dog",
      "breed": "Border Collie",
      "sex": "female",
      "size": "medium",
      "bio": "Texto",
      "photos": ["https://..."],
      "distance_km": 2.4,
      "comuna": "Providencia",
      "temperament_tags": ["sociable"],
      "looking_for": ["walk", "playdate"],
      "compatibility_score": 0.94
    }
  ],
  "next_cursor": null
}

Reglas:
- No devolver coordenadas ni dirección exacta.
- Excluir mascotas propias, bloqueadas, reportadas, suspendidas y ya evaluadas.
- Aplicar preferencias de distancia, tamaño, edad, sexo e intereses.


2. POST /discovery/swipes
-------------------------
Body:
{
  "actor_pet_id": "uuid",
  "customer_id": "uuid",
  "target_pet_id": "uuid",
  "decision": "like|pass|super_like"
}

Respuesta:
{
  "matched": true,
  "match": {
    "id": "uuid",
    "pet_ids": ["uuid", "uuid"],
    "created_at": "ISO-8601"
  }
}

Debe ser idempotente y crear el match en una transacción solamente cuando el
interés sea mutuo.


3. POST /discovery/swipes/undo
------------------------------
Body:
{
  "actor_pet_id": "uuid",
  "customer_id": "uuid",
  "target_pet_id": "uuid"
}

Respuesta: { "ok": true }

Regla: definir una ventana de tiempo o consumo de beneficio para deshacer.

PRIORIDAD 3 - NOTIFICACIONES PUSH

20. Servicio interno de envío push
-----------------------------------
No debe exponerse directamente a la app.

Eventos mínimos:
- match creado;
- mensaje de match;
- mensaje de reserva;
- reserva aceptada/rechazada;
- servicio por comenzar;
- servicio iniciado/pausado/reanudado/finalizado;
- proveedor acercándose;
- nueva foto o incidente;
- SOS recibido/actualizado;
- recordatorio de reserva.

Debe guardar recibos, reintentos, errores y eliminar tokens inválidos.

PRIORIDAD 5 - EXPERIENCIA DEL SERVICIO
======================================

27. POST /create-provider-review
--------------------------------
Esta es la ruta que la aplicación actual ya espera.

Body:
{
  "customer_id": "uuid",
  "booking_id": "uuid",
  "provider_id": "uuid",
  "rating": 1,
  "comment": "texto opcional"
}

Respuesta:
{
  "review": {
    "id": "uuid",
    "verified": true,
    "rating": 5,
    "comment": "Excelente servicio",
    "created_at": "ISO-8601"
  }
}

Reglas:
- Sólo el cliente dueño de una reserva completada puede opinar.
- Una reseña por reserva.
- provider_id debe salir de la reserva, no confiar en el body.


28. GET /bookings/{booking_id}/eta
----------------------------------
Respuesta:
{
  "eta_at": "ISO-8601|null",
  "eta_minutes": 8,
  "distance_meters": 2300,
  "calculated_at": "ISO-8601"
}

La interfaz hoy muestra la hora de reserva o última señal GPS como respaldo.
Esta API permite entregar una ETA real usando la posición y destino.


29. GET /bookings/{booking_id}/timeline
---------------------------------------
Respuesta:
{
  "items": [
    {
      "id": "uuid",
      "type": "requested|accepted|arriving|checked_in|started|paused|photo|incident|completed|cancelled",
      "actor_role": "customer|provider|system|admin",
      "created_at": "ISO-8601",
      "data": {}
    }
  ]
}

El historial debe ser append-only para servir como evidencia operacional.


30. POST /bookings/{booking_id}/provider-arrival
------------------------------------------------
Body:
{
  "latitude": -33.45,
  "longitude": -70.66,
  "accuracy": 10
}

Respuesta: { "ok": true, "arrived_at": "ISO-8601" }

Validar cercanía con el punto de retiro y notificar al cliente.


31. Moderación automática de evidencia
---------------------------------------
POST /internal/moderation/photos

Uso interno después de subir una foto de mascota o servicio. Debe registrar:
- resultado automático;
- confianza;
- categorías detectadas;
- estado pending|approved|rejected|manual_review;
- revisor y resolución si hubo revisión humana.


ORDEN RECOMENDADO DE IMPLEMENTACIÓN
===================================

Fase A, imprescindible para retirar el modo local:
1) discovery/candidates
2) discovery/swipes y undo
3) matches y mensajes
4) blocks y reports
5) preferencias y perfil social

Fase B, operación en teléfonos reales:
6) register-push-token
7) servicio interno de push
8) create-provider-review
9) SOS dedicado y contactos de emergencia

Fase C, experiencia avanzada:
10) ETA real
11) timeline auditable
12) compartir seguimiento
13) disputas
14) moderación automática y consola administrativa


CONFIGURACIÓN EXTERNA NECESARIA (NO ES API)
===========================================

- Crear/configurar proyecto EAS para obtener projectId.
- Configurar credenciales FCM v1 para Android.
- Configurar APNs y credenciales Apple para iPhone.
- Configurar almacenamiento privado para fotos/evidencias.
- Definir retención y acceso a ubicación, incidentes y evidencia.
- Crear trabajadores/colas para push, moderación y alertas SOS.
ACTUALIZACION DE PERFIL CLIENTE (bloqueante para sincronizacion multidispositivo)
-------------------------------------------------------------------------------
PUT /customers/{customer_id}
Body parcial: full_name, first_name, last_name, phone, address, comuna, city.
Debe devolver el Customer actualizado. Actualmente responde 405 method_not_allowed.
ACCIONES DE RESERVA CREADA POR CLIENTE (bloqueante)
---------------------------------------------------
Las reservas nuevas se crean en nod-api /bookings, pero la API provider pertenece a otro proyecto
y /get-provider-bookings no las devuelve. nod-api necesita endpoints para que el proveedor opere:
POST /bookings/{booking_id}/accept
POST /bookings/{booking_id}/reject
Body: { provider_id, reason opcional }
